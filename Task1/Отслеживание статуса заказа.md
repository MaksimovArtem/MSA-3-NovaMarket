Статус заказа зависит от разных сервисов и диаграмма последовательности будет или слишком громоздкой, или слишком неполной, тч опишу текстом

Запрашивать статус пользователь будет у Сервиса Заказов через API шлюз:

```
Пользователь -> API Шлюз -> Сервис Заказов
```

В разные моменты времени статус заказа будет разный(см. диаграмму оформления заказа для большей информации)
События `DeliveryStarted` и `DeliveryFinished` не отражены на диаграмме оформления заказа для простоты, но отражены на C2 диаграмме


После получения сервисом заказов события:

- `'OrderCreated'` статус заказа становится "Ожидает подтверждения"
- `'StockReservationSucceeded'` статус заказа становится "Ожидает оплаты". В этот момент сервер забронировал товары и они зарезервированы за заказом. В рамках MVP события на время оплаты намеренно опускаются, тч ждать оплату сервер будет вечно
- `'PaymentSucceeded'` статус заказа становится "Оплачен"
- `'PaymentSucceeded'` статус заказа становится "Ошибка при оплате"
- `'DeliveryCreated'`  статус заказа становится "Доставка создана". В этот момент клиент получает трекинг-номер
- `'DeliveryStarted'`  статус заказа становится "Доставка отправлена". В этот момент клиент получает примерное время доставки
- `'DeliveryFinished'`  статус заказа становится "Доставка завершена". Конечное состояние заказа
